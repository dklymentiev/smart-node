# /srv — Smart Node agent base (root prompt)

This file is the master prompt inherited by everything under `/srv/`.
It is part of the static base laid down by the Smart Node installer. The
**registry source of truth is the database** (`sn_config`); files under
`/srv/agents/<name>/` that carry agent data are GENERATED by the controller
(`core-api`) from that database. Do not hand-edit generated files — change the
database through the panel and let the controller re-render.

## Universal rules (inherited by all of /srv)

- **Language:** code and documentation in English.
- **No emoji** anywhere in code, output, or docs. Use `[OK]` / `[ERROR]` markers.
- **No hardcoded secrets.** Everything via `.env` files under `/srv/secrets/`
  or the secrets manager. Never commit a real secret (only `*.example`).
- **Time:** the node's timezone. **Dates:** `YYYY-MM-DD`. **Timestamps:** `YYYY-MM-DD-HHMMSS`.
- **Logs:** each run writes `logs/YYYY-MM-DD-HHMMSS.log` and updates the
  `logs/latest.log` symlink to point at the most recent run.

## Directory layout

```
/srv/
├── CLAUDE.md            # this file — root rules
├── README.md            # human-facing overview
├── agents/              # one folder per agent (see agents/CLAUDE.md)
│   ├── _template/       # canonical agent skeleton (static)
│   └── <name>/          # provisioned by core-api from the DB
├── tools/               # reusable tools, callable by agents and Claude Code
├── secrets/             # .env files / secrets manager — never hardcode
└── scripts/             # shared utilities
    └── lib/             # logging.sh, env.sh
```

Source-of-truth boundary:
- **static** (shipped by installer): this file, `agents/_template/`,
  `scripts/lib/`, convention `CLAUDE.md`s.
- **generated** (rendered by `core-api` from `sn_config`): per-agent
  `CLAUDE.md`, `agent.yaml`, `config.json`; `tools/`; rendered crontab.

## How an agent is woken

Not from here. An agent folder has no entry point: the Runner
(`smart-node-runner`) wakes an agent that has work through brin, and
the turn runs in a gateway session with the folder as its working directory.
That is the one path, and it is the one that records the session, its usage and
its budget. The per-agent `run.sh` that cron used to call was retired when the Runner became the sole waker; do not recreate it.

Scheduled node jobs still exist (`sn_config.crons`, rendered by the
`cron-runner` companion into the system crontab); they are not how agents wake.
